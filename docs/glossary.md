# Glossary

| #  | Term                         | Abbreviations | Meaning                                                                                                                               | What it is not                                                                                                   |
|----|------------------------------|---------------|---------------------------------------------------------------------------------------------------------------------------------------|------------------------------------------------------------------------------------------------------------------|
| 1  | Technical Debt               | TD            | Trade-offs between short-term development productivity and long-term code quality                                                     | General poor code quality; must represent a conscious deferral                                                   |
| 2  | Security Debt                | SD            | A subset of Technical Debt specifically concerning deferred security-related tasks that leave systems potentially vulnerable          | General Technical Debt; must be security-specific                                                                |
| 3  | Self-admitted Technical Debt | SATD          | Technical debt that is explicitly acknowledged by the developer in project artefacts (e.g. comments, commits, issues)                 | Undisclosed or unintentional debt; must be explicitly stated by the author                                       |
| 4  | Self-admitted Security Debt  | SASD          | A subset of SATD specifically relating to security concerns, acknowledged by the developer across project artefacts                   | General SATD; must be security-related                                                                           |
| 5  | Artefact                     | —             | A discrete unit of developer-produced content ingested for analysis: a commit message, code comment, issue, or pull request           | Binary build outputs or compiled assets; must be textual and developer-authored                                  |
| 6  | Commit Artefact              | —             | An artefact derived from a VCS commit, comprising a title and body                                                                    | The code changes (diff) within a commit; refers to the message only                                              |
| 7  | Issue Artefact               | —             | An artefact derived from a VCS issue, comprising a title, description, and labels                                                     | A bug report in the abstract; must be sourced from a VCS issue tracker                                           |
| 8  | Code Artefact                | —             | An artefact derived from source code file content                                                                                     | A compiled or binary file; must be raw, human-readable source code                                               |
| 9  | Pull Request Artefact        | PR Artefact   | An artefact derived from a pull request, comprising a title, description, and labels                                                  | Code review comments or inline annotations; refers to the PR description only                                    |
| 10 | Artefact Label               | —             | A tag attached to an Issue or Pull Request Artefact with a name and description                                                       | A code annotation or linting tag                                                                                 |
| 11 | NLP Analysis                 | —             | The structured output produced by the NLP pipeline for a given artefact, comprising a SASD analysis and CWE mapping                   | A raw model response; must be deserialised into domain entities                                                  |
| 12 | SASD Analysis                | —             | A component of NLP Analysis indicating whether an artefact contains SASD, with an explanation and severity rating                     | The full NLP Analysis; scoped to SASD detection and classification only                                          |
| 13 | CWE Mapping                  | —             | A component of NLP Analysis that maps a detected SASD instance to one or more Common Weakness Enumerations                            | A generic vulnerability report; must reference the standardised CWE framework                                    |
| 14 | Common Weakness Enumeration  | CWE           | A community-developed list of software and hardware weakness types, used as a structured framework for categorising security findings | CVE (Common Vulnerabilities and Exposures); CWE describes weakness *types*, not specific vulnerability instances |
| 15 | Severity                     | —             | A classification of the impact of a detected SASD instance: LOW, MEDIUM, HIGH, or CRITICAL                                            | Priority; severity describes impact, not remediation urgency                                                     |
| 16 | NLP Gateway                  | NlpGateway    | The internal system component responsible for passing artefacts to the LLM and returning structured analysis results                  | The LLM itself; the gateway is the interface layer, not the model                                                |
| 17 | Large Language Model         | LLM           | A pre-trained AI model used for natural language understanding and generation, used here for SASD detection and CWE mapping           | A bespoke or fine-tuned model; the tool relies on existing pre-trained models only                               |
| 18 | Version Control System       | VCS           | A system for tracking changes to source code (e.g. GitHub); the source of artefact ingestion                                          | A general file storage system; must support structured artefact retrieval via API                                |
| 19 | Repository                   | Repo          | A VCS-hosted project from which artefacts are fetched for analysis                                                                    | A local directory; in this context refers to a remotely hosted, URL-addressable repository                       |
| 20 | File Browser                 | FileBrowser   | A UI component that renders the file tree of a loaded repository, allowing users to navigate and select source code files             | A general OS file explorer; scoped to the web client and loaded repository context only                          |
| 21 | File Viewer                  | FileViewer    | A UI component that renders the content of a selected source code file for viewing and inline analysis highlighting                   | A code editor; the FileViewer is read-only                                                                       |
| 22 | Session                      | —             | A single, transient interaction with the tool during which artefacts are ingested and analysed; no data persists beyond this scope    | A user account or persistent workspace                                                                           |
